# Teacher Portal: запуск з нуля через Supabase Dashboard

Ця інструкція для **нового порожнього Supabase-проєкту**. Не потрібно
встановлювати Supabase CLI, Docker або запускати команди в терміналі.

> Важливо: виконуй тільки файл `supabase/production_schema.sql`. Старий
> `supabase/schema.sql` був для локального прототипу і для нового проєкту не підходить.

## Крок 1. Відкрити SQL Editor і створити базу

1. Відкрий [Supabase Dashboard](https://supabase.com/dashboard) і вибери щойно
   створений проєкт.
2. Зліва натисни **SQL Editor**.
3. Натисни **New query** у верхній частині екрана.
4. У цьому проєкті відкрий файл
   [`supabase/production_schema.sql`](./supabase/production_schema.sql).
5. Виділи весь текст у файлі, скопіюй його та встав у порожній редактор Supabase.
6. Натисни кнопку **Run** або `Ctrl + Enter`.
7. Дочекайся зеленого повідомлення про успішне виконання.

Файл створює таблиці, ролі, правила доступу, приватний bucket `portal-files`,
календар, домашні завдання і фінансовий журнал. Його потрібно запускати **один
раз** у чистому проєкті.

### Якщо SQL не запускається

1. Переконайся, що відкрито саме новий проєкт, а не попередній.
2. Перевір, що проєкт має статус `Active`, а не `Paused` або `Restoring`.
3. Не запускай тільки частину файлу: порядок команд у ньому важливий.
4. Якщо з'являється червона помилка, скопіюй її текст сюди. Не надсилай URL,
   publishable key, пароль чи `service_role` key.
5. Якщо кнопка **Run** неактивна, перезавантаж Dashboard і створи саме **New query**,
   а не переглядай приклад або збережений запит.

### Виправлення помилки `operator does not exist: text = uuid`

Якщо це була перша спроба запуску схеми, не запускай увесь файл повторно: усі
попередні команди вже могли успішно створити таблиці. Створи **New query** і
виконай тільки цей фрагмент:

```sql
create policy "portal_files_delete_owner" on storage.objects for delete to authenticated using (
  bucket_id = 'portal-files' and owner_id = auth.uid()::text
);
```

Після зеленого повідомлення продовжуй з кроку 2.

### Почати з чистого стану після невдалої першої спроби

Якщо у `Table Editor` немає таблиць Teacher Portal, але при повторному запуску
бачиш помилку на кшталт `policy already exists`, виконай повне очищення саме
цього нового проєкту:

1. У **SQL Editor** створи **New query**.
2. Скопіюй і виконай весь файл
   [`supabase/reset_new_project.sql`](./supabase/reset_new_project.sql).
3. Після зеленого результату створи ще один **New query**.
4. Запусти весь актуальний
   [`supabase/production_schema.sql`](./supabase/production_schema.sql).

`reset_new_project.sql` видаляє лише об'єкти Teacher Portal. Bucket
`portal-files` лишається, а production-схема безпечно оновить його налаштування.
Не запускай цей reset після створення реальних акаунтів, файлів або занять.

Supabase офіційно підтримує створення таблиць і функцій через `SQL Editor → New
Query → Run`. [Довідка Supabase](https://supabase.com/docs/guides/database/functions?example-view=sql&language=sql&queryGroups=example-view&queryGroups=language)

## Крок 2. Увімкнути email-вхід для тестування

1. Зліва відкрий **Authentication**.
2. Відкрий розділ **Providers** або **Sign In / Providers**.
3. Відкрий **Email** і переконайся, що він увімкнений.
4. Для першого тесту вимкни вимогу підтвердження email (`Confirm email`).
5. Збережи зміни.

Після того як сайт запрацює на Vercel, підтвердження email краще знову увімкнути.

## Крок 3. Взяти безпечні публічні ключі

1. Відкрий **Project Settings → API Keys**.
2. Скопіюй `Project URL`.
3. Скопіюй **Publishable key**. Якщо такого підпису немає, візьми `anon` key.
4. У локальному файлі [`assets/config.js`](./assets/config.js) заповни поля:

```js
window.TEACHER_PORTAL_CONFIG = {
  supabaseUrl: "https://YOUR-PROJECT.supabase.co",
  supabaseAnonKey: "YOUR_PUBLISHABLE_OR_ANON_KEY",
  schoolName: "Назва твоєї школи"
};
```

`Publishable` / `anon` key можна використовувати у браузері: правила RLS зі
схеми обмежують доступ до даних. **Ніколи** не вставляй у файл або чат
`service_role` / secret key.

## Крок 4. Створити Edge Function для адмін-панелі

Без цієї функції працюватимуть заявки, уроки, фінанси й файли, але admin не
зможе створювати користувачів вручну, змінювати ролі, призупиняти або видаляти
акаунти.

1. У Supabase Dashboard відкрий **Edge Functions**.
2. Натисни **Deploy a new function**.
3. Обери **Via Editor**.
4. У назві функції введи рівно `admin-users`.
5. У цьому проєкті відкрий
   [`supabase/functions/admin-users/index.ts`](./supabase/functions/admin-users/index.ts).
6. Замінюй увесь код у редакторі Supabase на код з цього файлу.
7. Натисни **Deploy function** і дочекайся успішного повідомлення.

Для цієї функції не потрібно вручну додавати `service_role` key: вона бере
стандартні серверні змінні Supabase тільки всередині захищеного середовища.
Dashboard дозволяє створити та задеплоїти Edge Function прямо у браузері.
[Офіційна інструкція](https://supabase.com/docs/guides/functions/quickstart-dashboard)

## Крок 5. Опублікувати staging-сайт на Vercel

1. Збережи зміни у репозиторії, включно з `assets/config.js`, і відправ їх у GitHub.
2. Увійди у [Vercel](https://vercel.com), натисни **Add New → Project**.
3. Імпортуй цей GitHub-репозиторій.
4. У налаштуваннях проєкту обери `Other` як Framework Preset.
5. Не вказуй Build Command. Output Directory залиш `.`.
6. Натисни **Deploy**.
7. Скопіюй адресу на кшталт `https://teacher-portal-xxx.vercel.app`.

## Крок 6. Додати адресу сайту в Supabase Auth

1. Повернись у Supabase → **Authentication → URL Configuration**.
2. У **Site URL** встав адресу staging-сайту з Vercel.
3. У **Redirect URLs** додай цю саму адресу з `/**` наприкінці, наприклад:
   `https://teacher-portal-xxx.vercel.app/**`
4. Збережи зміни.

Це потрібно для підтвердження email і майбутнього відновлення пароля.
[Як працюють Site URL та Redirect URLs](https://supabase.com/docs/guides/auth/redirect-urls)

## Крок 7. Створити першого адміністратора

1. Відкрий адресу staging-сайту.
2. Зареєструй свій перший акаунт як учень або викладач.
3. Після входу сайт покаже екран початкового налаштування.
4. У правій формі введи назву школи й своє ім’я.
5. Натисни **Створити школу та admin-доступ**.
6. Переконайся, що відкрився розділ **Огляд школи** з роллю адміністратора.

Ця дія доступна лише для першого акаунту в чистій базі.

## Крок 8. Коротка перевірка всіх ролей

1. Під admin створи або підтвердь одного викладача й одного учня.
2. Створи предмет, прив'яжи учня до викладача та задай тариф у цілих гривнях.
3. Під викладачем створи урок і зміни його статус на `Проведено`.
4. Під admin перевір у **Фінансах**, що з'явилося списання та нарахування.
5. Під викладачем опублікуй домашнє з PDF або зображенням.
6. Під учнем надішли відповідь і файл; під викладачем перевір та прикріпи відповідь.
7. Під учнем переконайся, що не видно цін, гаманця та редагування статусів уроку.

## Якщо щось зупинилось

Надішли один скріншот або точний текст помилки й напиши, на якому кроці вона
з'явилася. Ключі, паролі та персональні дані на скріншоті закрий перед надсиланням.
